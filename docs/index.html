Features

Everything you need, nothing you don't

Built for developers who want power without complexity.

Auto-Detection

Point RunPort at a project folder. It reads your package.json, detects your framework (Next.js, Vite, Angular, NestJS…), and pre-fills the start command. Zero manual config.

Floating Desktop Widget

A compact, always-on-top widget floats above your code editor. Start or stop any server with one click — without switching away from what you're working on.

Smart Port Conflict Resolver

When a port is occupied, RunPort tells you exactly which process is using it. Kill it with one click, or let RunPort automatically pick the next free port.

Live Log Streaming

Watch server output in real time — startup messages, build errors, request logs. Batched at 50 ms intervals for smooth display even under high-velocity output.

Git Branch & Uptime Tracking

See your active Git branch and how long each server has been running at a glance. No more switching to a terminal just to check git branch.

System Tray Integration

Minimize RunPort to the system tray and keep your taskbar clean. Right-click the tray icon for Start All / Stop All — no window needed.

Case Study

How RunPort was built

From a recurring daily frustration to a working desktop product.

The Problem

As a developer working across multiple client projects, the morning routine became a ritual of friction: open terminal, cd into project A, remember the right command, repeat for project B, then C. By midday, there were eight terminal tabs open. Switching between them meant reading tab labels and hoping you picked the right one. When a port conflict appeared, you had to dig through process lists manually.

The question was simple: why should managing a running process be harder than managing an open application?

The Vision

A dashboard where every project is a row. Green dot = running. One click to start, stop, or restart. The port and local URL visible at all times. Log output one tab away. No terminal required for day-to-day use.

The MVP spec was kept deliberately small: add a project, save it, detect its dev server, start it, stop it, view its logs. If those 11 things worked reliably, the tool already delivered real value.

What Was Built

RunPort shipped with:

  • Auto-detection of 11 frameworks and 4 package managers
  • A full project lifecycle — start, stop, restart, open in browser
  • Live log streaming with filter and clear controls
  • Git branch display and real-time uptime counters
  • A floating always-on-top widget for 1-click control without leaving your editor
  • A smart port conflict resolver with 1-click PID kill or auto next-free-port
  • System tray with Start All / Stop All

Challenges Solved

Process Tree Killing on Windows
When you stop a Node.js dev server on Windows, the parent process exits but child processes (the actual server) linger. RunPort uses tree-kill to terminate the entire process group, not just the parent — ensuring no orphan processes consume your ports.
High-Velocity Log Output
During a Vite cold build, hundreds of log lines arrive in milliseconds. Naïve per-line IPC messaging caused the UI to freeze. RunPort batches log messages at a 50 ms interval and maintains a bounded memory buffer — the UI stays responsive regardless of output rate.
Frameless Transparent Widget Window
A floating widget that looks native on Windows requires a frameless, transparent Electron window with always-on-top behavior and correct hit-testing so drag works but clicks pass through transparent regions.
